1what is it

dictation that can also do things.

x is a fork of hex. press a key, talk, and your words are typed like always. start with friday and it treats the sentence as a command.

commands go through a small set of steps it can actually run: open an app, search a site, switch workspace, type into a window it just opened, or operate a browser tab.

it only calls a job done when it can see proof on screen. no proof, it says so.

2what makes it different

most voice tools type. x acts, then checks.

for browser work it looks at the page through the accessibility tree, picks one step, does it, looks again. observe act verify, up to fifteen times, then it stops.

whatever is on the page is treated as data, not orders. a page that says "ignore your instructions" gets read like any other text. it can't leave the list of steps.

3installation

arch first. one script, or the aur.

x86_64 only for now. i've only run it on arch with hyprland, so treat other setups as untested.

bash
git clone https://github.com/0xQuerencia/x && cd x
./scripts/install-arch.sh
systemctl --user enable --now x.service
x labs on x-agent
bash
# package files are in packaging/aur-x
cd packaging/aur-x && makepkg -si
bash
sha256sum x-0.1.0-alpha.1-linux-x64
# compare with the .sha256 file on the release

x keeps its own data in ~/.local/share/x and runs as x.service, so it can sit beside a normal hex install.

for browser control, chromium and chrome need --force-renderer-accessibility. then grant the app once: x agent computer grant chromium.

4what you get

what it can do today.

  • open and switch apps, jump workspaces on hyprland
  • search youtube, github, wikipedia and a few more
  • start opencode in a fresh folder, interactive or headless
  • risky steps ask first, and a stop button always works
  • click, type and navigate in a browser you have granted
  • done means it saw the result on screen
  • never types into password fields or presses send, buy or delete
  • transcription runs on your machine; use a local planner model to keep it all there
  • free and open source, mit licensed, built on hex

frequently asked questions

1does it send my voice to the cloud?

no. transcription runs on your machine. only the sentence you said goes to a planner model, and you pick that model. an ollama model keeps even that local.

2what can the browser part see?

window titles, button and link names, and page text, read through accessibility. never passwords or form values. that text only goes to a model on your own machine unless you switch on x agent computer remote on.

3can it click anything?

no. sending, buying, deleting, signing in and similar buttons are refused. it only works in apps you grant, and browsers only. you can revoke a grant at any time.

4is this a finished release?

no. it's an alpha. the pieces were tested one by one on a single machine. the full spoken flow is still being checked.

5which systems does it run on?

linux, x86_64. i built and tested it on arch with hyprland. there are no mac or windows builds.

6how is it related to hex?

x is a fork. hex's local dictation is untouched, and x adds the agent on top. both can be installed together because x keeps its own folders.

7why "friday"?

"x" got mis-heard too often. the wake word is a rule in the code, and "x" still works as a backup.

8how do i stop it mid-task?

press stop in the agent pane or run x agent stop. browser tasks also end themselves after fifteen steps, three errors or three minutes.
